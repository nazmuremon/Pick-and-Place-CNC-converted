# 02 – Architecture

## System diagram

```
┌───────────────────────── Raspberry Pi 5 (8 GB) ─────────────────────────┐
│ Python app                                                               │
│  job planner · vision (OpenCV) · calibration · safety checks · web UI    │
└────┬──────────────────────────────────────────┬────────────────┬─────────┘
     │ USB serial                               │ USB            │ CSI
     │ (G-code, also the nozzle servo, D18)     │                │
┌────▼───────────┐                            Top camera       Bottom camera
│ Pico + grblHAL │                            + LED ring       + LED ring
│ 3 axes + I/O   │                            (on the head,    (fixed,
└─┬────┬────┬──┬─┘                             looks down)      looks up)
  │    │    │  │ Outputs: grblHAL runs them only after the queued moves (D3, D18)
  │    │    │  ├─ Spindle PWM, 50 Hz ← M3 S<us> / M5 ──▶ MG995 servo = nozzle rotation (own 5–6 V supply)
  │    │    │  ├─ Flood coolant      ← M8 / M9 ──▶ MOSFET ──▶ vacuum pump
  │    │    │  └─ Mist coolant       ← M7 / M9 ──▶ MOSFET ──▶ solenoid valve   (MOSFETs + flyback diodes)
  │ STEP/DIR/EN through a 5 V buffer (74HCT245 / 74ACT245)
  ▼    ▼    ▼
 X drv Y drv Z drv
  │    │    │
  X    Y    Z
Inputs to Pico: E-stop (NC contact), driver ALARM outputs, 3 spare inputs for limit switches later
```
There is no second controller: the servo pulses come from the motion controller itself (D18).
On the bench Uno this runs now, with our Grbl build ([../firmware/README.md](../firmware/README.md)).
On the Pico with grblHAL the same mapping is planned: to be checked when there is a Pico (the owner has none now).

## Who does what

| Part | Job | Does NOT do |
|---|---|---|
| Raspberry Pi 5 | Plans the job, runs vision, calibration and the UI, checks soft limits, sends G-code, logs | Step pulses, anything that needs exact timing |
| Pico + grblHAL | Step pulses, acceleration, moving the axes together (X, Y, Z), pump and valve timing, the nozzle servo pulses (spindle PWM, D18), E-stop input | Vision, job logic, angle → pulse width (the app does it from the calibration table) |
| Stepper drivers | Drive the motors (closed-loop drivers also correct small errors and report ALARM) | — |
| Top camera | HOME mark, bed survey (all labels), feed-tray scan, board holes or fiducials, checking picks | Reading part values (it can only measure size) |
| Bottom camera | Part offset and angle on the nozzle (phase 7), finding the nozzle tip | — |

## Data flow for one job

```
bed.yaml (labels) ──▶ bed survey (top camera) ──▶ slot zones in machine mm, PCB area from bed.yaml
                                                   (used by the scan, the placement checks and safety)

KiCad board ──pcbnew──▶ placement list (ref, value, footprint, x, y, rot, side)
                               │
feeder.yaml ───────────────────┤──▶ job planner ──▶ loads of ≤ 5 lines (which line goes in which slot)
                               │                      │
                               │              operator lays a tape strip in each slot (load sheet / QR scan)
                               ▼                      ▼
                     board registration        feed-tray scan (top camera)
                     (holes/fiducials)          → part positions + angles along each strip
                               │                      │
                               └──────▶ pick/place loop ◀──────┘
                                          │  G-code (the nozzle angle too: M3 S<us>, D18)
                                          ▼
                                    Pico + grblHAL ──▶ motors, pump, valve, MG995 servo
```
The bed survey runs once after the labels are stuck, and again if a label moves.
